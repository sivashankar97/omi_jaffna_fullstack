Slide 03 · Why it exists

One digital home for the Province

For visitors
  • Discover who the Oblates are in Jaffna (history, charism, leadership)
  • Explore ministries, parishes, vocations, international mission
  • Read news, media, library resources
  • Find houses, contact details, and the mission map
For the Province team
  • Staff edit pages and content from /admin CMS
  • Fathers use /login → personal dashboard (not CMS)
  • News submissions go to review before publish
  • Inquiries from Contact land in the CMS inbox
Brand promise on the site

“17 Ministries. Many Places. One Mission.” — with a living calendar of birthdays, events, and necrology memory.

Slide 04 · Architecture

Three parts, one product

1
Public site

Next.js app (`site/`) — pages, glass UI, motion, map. Local: :5173

2
CMS

React admin built into `/admin` — staff only. Same host as the site.

3
API + database

Express (`api/`) :4000 · Postgres content & media · Netlify Function in prod

Content

Items (news, priests, ministries…) + page “blocks” for editable text/images.

Media

Uploads via `/api/files/…`. Stores in Postgres blobs, disk, or Supabase Storage.

Hosting

Netlify only — site + API function + static `/admin` build.

Slide 05 · Design system

Visual language visitors notice

Colour Sky cyan + gold

Primary #48cae4 · Nav teal #17b3c6 · Accent gold #ffbf00 / #ffcf4a · Page wash light blue #dff6fb

Surfaces Crystal-glass UI

Frosted cards, calendar stages, media bento, soft borders — used on Home, History, Ministries, Media.

Motion Motion for React

Keyvo-style hero / stagger / float reveals on Home and History. Scroll-safe (no flicker).

Header pattern (current)

White top strip with larger logos + short centered search · Floating cyan glass nav pill with all page links · Login (white) + Register (gold) in a row with spacing · No dark-mode toggle · Hero video still loads under the home page.

Slide 14 · Member portal

Login · Register · Father dashboard

1
Register / Login

Public `/register` & `/login`. Fathers authenticate against API sessions.

2
Header chip

Guest sees Login + gold Register. Signed-in Father sees name menu → dashboard / sign out.

3
Dashboard

`/dashboard` — profile, own items, news draft submissions, uploads, admin reports to fathers.

Security split

Fathers never use `/admin`. Staff (admin / publisher / editor) use CMS email login. Father sessions hitting admin are redirected to the public dashboard.

Slide 17 · Technical snapshot

How it runs

Frontend

Next.js App Router · React · Tailwind · Motion · Leaflet

Backend

Express API · role-aware auth · CRUD items · asset streaming

Data

Postgres · SQL migrations · optional Supabase Storage

Local

`npm run dev` → site :5173 · API :4000 · CMS /admin
After CMS code changes: `npm run cms:build`

Production

Deploy from `site/` with Netlify CLI
`netlify deploy --prod …` (manual; ~3–10 min)
